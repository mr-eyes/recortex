Questions and answers

Short answers. If yours is not here, the search at the top reads every page.

Does it work without the observer?

Yes. The brief at the start of each session, the commands and manual recording all work without it. The observer is optional, and it does nothing until you choose a level for a project folder on your machine.

Does recortex follow the work throughout a conversation?

Yes. Once you enable the observer for a project, it follows the conversation as you work. It can pick up a choice or a reported failure, and Claude can use that evidence when the topic comes up. Hooks trigger short bursts of work during the session. Between them the worker is idle or exits.

Does it need a public repository?

No. The record can live in this repository's issues, in another one, or in a new private one. Everything in it is as visible as that repository is, so a private repository keeps it private.

What does it cost?

Tokens and calls, never a price. Under a Claude subscription the observer's calls count against your usage limits, at most 80 sorting, 70 note-taking and 8 paper-text calls a day for a project. /recortex:usage shows what was used. More

How do I stop the observer from posting to GitHub?

For one session, send off the record as a separate message. Before sharing more, check that the session's publication hold is active. Earlier posts stay on GitHub.

For the project, ask Claude for the full path to the installed skills/recortex/scripts/observer.py. From your project folder in a separate terminal outside Claude Code, substitute that path in python3 "/path/to/observer.py" pause publication. This pauses automatic posts from this machine. Capture and review can continue. To turn off the observer for this folder, run python3 "/path/to/observer.py" disable. If a hold applies, type disable to confirm.

At setup, choose “Later” to leave the observer off. To try it without automatic posting, see how to enable shadow mode and what happens to queued notes.

Does it read my code and files?

The observer takes its evidence from what you typed, what Claude told you, the plans you approved and the options you chose. It skips tool output, file contents, web pages and command results. Its model calls can also include selected parts of the trusted project record.

What if it records something wrong?

For a posted note, post a correction that points back to it. For a task the observer opened or closed, or a list it rendered, ask Claude for the installed path to skills/recortex/scripts/observer.py. From your project folder in a separate terminal outside Claude Code, run python3 "/path/to/observer.py" log with that path. Find the number after act on the line you want. Run python3 "/path/to/observer.py" undo ACT with that number and type undo to confirm.

What if I edit an issue by hand?

You can. A note that anyone but an allowed account edited is not told to a session. A checkbox you tick on GitHub is not believed; the session asks whether to record it or put it back. A topic body is replaced only after the script checks that it is still the one it started from.

Why GitHub issues?

Your team can read the published record in a browser using the access you already manage. recortex can rebuild its local index from those issues. Unpublished notes and your settings live on your machine.

Is it only for software?

A research group can track why an observation was excluded, a software team can check why a rollout was held, and a designer can recover the reason for a prototype choice. Each uses the same project record. Reports and papers

Yes. You name who can make decisions, and each person sets their own trust, writing mode and observer level on their own machine. Who decides

Why does no brief appear?

Usually the repository is not in your trusted list yet, or the local copy could not be refreshed. Ask Claude to run hooks.py --doctor. It says why, in plain words, and changes nothing.
