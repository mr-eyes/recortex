Upgrading

Update the plugin the way you update any Claude Code plugin, then start a new session. Your record on GitHub and your project file keep working as they are.

From 1.4.0

Version 1.5.0 added the observer's several jobs. Here is what the first session after the update asks of you.

  • The level questionIt comes in the batch of setup questions. An observer that was on with 1.4.0 stays paused until you answer: no hook captures, no worker runs and no model call is made. Your earlier choice of model is not carried over as consent to the new jobs.
  • The stronger modelIn a project with a plan, a writing mode other than off and the level Assistant or Everything, you are also asked whether Opus may draft the paper's text. "No" keeps it off.
  • Every machine on a teamUpdate them all before the observer opens the first task. An older version reads a task's steps as an ordinary comment and shows no checkmarks.
  • Nothing to rebuild by handThe first sync derives the local index again from the stored comments, with no network and no change to the record.

New on your machine, all private: usage.db, which holds integers only, the folders of drafts that wait, and backups of task bodies. The plugin registers one more hook event, SubagentStop, which prints nothing and only counts a plugin agent's tokens.

From 1.5.0 to 1.5.1

Nothing to do. Three changes you may notice:

  • When you release a hold, what was held under it is offered again, and the other notes the observer held back go to what waits for your yes.
  • One message can be recorded as a failure and as the decision it led to.
  • The paper keeper's old draft folders are cleaned from your machine, a day at a time.

From the old marketplace

Until version 1.3.0 the plugin was installed from the mr-eyes-skills marketplace. From 1.4.0 the repository is {{repo}} and the marketplace is recortex. Four commands move an installed copy, one after the other:

{{cmd claude plugin marketplace add {{repo}} claude plugin install recortex@recortex claude plugin uninstall recortex@mr-eyes-skills claude plugin marketplace remove mr-eyes-skills }}
  • Then start a new session, and run claude plugin list. It shows recortex@recortex, version 1.4.0 or later.
  • If the list shows gh-issues-manager@mr-eyes-skills, uninstall that name in the third command.
  • Add --scope project or --scope local if that is how you installed it.
  • Do not run claude plugin marketplace update mr-eyes-skills instead: GitHub forwards the old address to the new repository, whose marketplace has another name.
  • Until the old copy is removed, every session shows two briefs. The same holds for any other copy, such as a folder install.

From gh-issues-manager

The plugin was named gh-issues-manager before version 0.5.0. After the move above, nothing else is needed. The old configuration file, folders, trusted list, GHIM_* variables and everything on GitHub keep working, and the earlier names are read for at least twelve months. Rename the configuration file to .recortex.json only once everyone on the project has 0.5.0 or later. hooks.py --doctor lists the earlier names still in use.
