Install

You need Claude Code, the GitHub CLI gh signed in to github.com, Python 3.8 or newer and bash. The plugin uses only the Python standard library.

{{cmd claude plugin marketplace add {{repo}} claude plugin install recortex@recortex }}

Start a new Claude Code session. Check that claude plugin list shows recortex@recortex. If you installed an earlier version, see Upgrading.

Set up the record

Open Claude Code in your project and say:

{{say Set up the record for this project. }}

Claude checks your GitHub sign-in and Python version. If either needs attention, it tells you what to run. It asks a few multiple-choice questions at a time and suggests answers based on your project.

  • What you’re making, such as software, a report, documentation or a paper, and its sections.
  • Where to keep the record. Use this repository’s issues, another repository, or a new private one.
  • Whose words count as project decisions.
  • Whether to keep a GitHub Projects board. The default is no.
  • Whether to trust this repository so the hooks may show its brief. Until then they leave out the record from GitHub.
  • How much the observer does and which model takes notes.

Review the summary. When you confirm, Claude creates the labels and pinned hub issue and builds the local index for your first brief.

If another account or an organization owns the repository, add your GitHub login after its name in your trusted list. For example, octo-org/sample-project octocat lets the dashboard show notes posted by octocat. Trusted list instructions

Choose the observer's level

Choose how much the observer may do as you work. Your answer gives it permission to act within that level.

  • Everything Recommended

    Notes, status, checkmarks, opening and closing tasks, and the board. It still asks before it changes a paper's text.

  • Assistant

    Notes, status and checkmarks. It asks before it opens or closes a task.

  • Notes only

    Notes and the status summary. Nothing else.

Choose “Later” to leave the observer off during setup. In shadow mode, the observer queues reviewed notes locally. Switching to automatic mode can post those earlier notes to GitHub. Using /recortex:record yourself posts to GitHub even in shadow mode. To try Notes only in shadow mode, ask Claude for the installed path to setup.py. From your project folder in your own terminal, run python3 "/path/to/setup.py" observer --level notes --mode shadow --yes with that path. Shadow mode setup

The observer needs a trusted repository. Its calls use your Claude allowance or the API key or provider you configured, up to 80 sorting, 70 note-taking and 8 paper-text calls a day for the project. What each level does

Your first session

First install recortex and set up a trusted record. Use a real choice from your project, or set up a practice repository for the scanned-pages example. Stay in the same chat.

  1. 1Make a choice as you work. Tell Claude what you chose and why. In the practice repository, say Put pages we can't date in an undated pile. I'd rather check them myself than put a page in the wrong year.
  2. 2
    Save this first decision. This command posts to GitHub even in shadow mode. Type /recortex:record my decision in my exact words, then refresh the local index. Claude creates a topic issue if needed, giving the observer a place for later notes. Wait for the GitHub comment link.
    Read the exact words in the example note

    “Put pages we can't date in an undated pile. I'd rather check them myself than put a page in the wrong year.”

  3. 3Try a different approach. Suggest the alternative you ruled out. For scanned pages, say Let’s give the undated pages the most likely year. Claude might reply, From the record: you chose to check each undated page yourself because a guess could put it in the wrong year. Should we make a review list or change the rule? If Claude leaves out the source, name your topic in a question like /recortex:ask Why do we keep an undated pile? and follow the comment link.
  4. 4Check your own source. Say show me the mind of this project to open your private dashboard. Choose What is settled? and select the decision sentence. Expand Where this was said and follow the link to the original GitHub comment. Compare the quoted decision with what you typed.

If a brief does not appear, ask Claude to run hooks.py --doctor. It says why: the configuration, the trust status, the index and its age. The script sits in the plugin's skills/recortex/scripts folder; from a terminal, run it from your project folder.

If you already have work

  • A project that has a recordInstall, add the repository to your trusted list, and open a session. The brief appears on its own.
  • A codebase with months of historySay catch up the record. Claude takes a read-only inventory of the commits, issues and pull requests, proposes a topic map for your approval, and posts past events as reconstructed notes with their original dates.
  • An older trackerSay migrate the issues of octo-org/octo-repo, with your own repository. Content is copied into the new structure. Nothing in the old tracker is edited or deleted.
