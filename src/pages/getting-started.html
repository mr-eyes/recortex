Getting started

Two commands to install, a few questions to set up, and one choice to make about the observer. Then you work as usual.

Install

You need Claude Code, the GitHub CLI gh signed in to github.com, Python 3.8 or newer and bash. The plugin uses only the Python standard library, so nothing else is installed.

{{cmd claude plugin marketplace add {{repo}} claude plugin install recortex@recortex }}

Start a new Claude Code session afterward. Check with claude plugin list: it shows recortex@recortex. If you installed an earlier version, see Upgrading.

Set up the record

Open Claude Code in your project and say:

{{say Set up the record for this project. }}

Claude checks first that gh runs and is signed in, and that Python is new enough. If something is missing it prints one line that says what to run, and stops. Then it asks multiple-choice questions, a few at a time, with its guesses pre-selected:

  • What the project will produce: software, a report, documentation, a paper, or something else, and the sections of each.
  • Where the record lives: this repository's issues, another repository, or a new private one.
  • Who decides: the people whose words count as decisions.
  • Whether to keep a board of the work on GitHub Projects. The default is no.
  • Whether to trust this repository, so that the hooks may show its brief. Until you do, a session is shown nothing from GitHub.
  • How much the observer does on its own, and which model takes the notes.

It ends with a summary and one confirmation. Nothing is written before that. Then it creates the labels and the pinned hub issue, and builds the first local index, so that your first session already has a brief.

Choose the observer's level

The setup asks this one exactly as printed, because your recorded answer is what lets it turn the observer on.

  • Everything Recommended

    Notes, status, checkmarks, opening and closing tasks, and the board. It still asks before it changes a paper's text.

  • Assistant

    Notes, status and checkmarks. It asks before it opens or closes a task.

  • Notes only

    Notes and the status summary. Nothing else.

"Later" leaves it off, and the question comes back after seven days. Choose "Other" and say "shadow" to try it at Notes only without posting anything. It needs the repository in your trusted list. Its calls count against your Claude usage, at most 80 sorting, 70 note-taking and 8 paper-text calls a day for the project. What each level does

Your first session

  1. 1The session opens with a short brief: where the record is, the open tasks and the focus. Its first line says how old the local copy it was made from is.
  2. 2Work as usual. The observer notes results, decisions and dead ends, and keeps the to-do list. Use /recortex:status whenever you want to see where things stand.
  3. 3Say pause here when you stop. It leaves a note of where things stand for the next session.
  4. 4Say show me the mind of this project to open the private page that tells the project in sentences.

If a brief does not appear, ask Claude to run hooks.py --doctor. It says why: the configuration, the trust status, the index and its age. The script sits in the plugin's skills/recortex/scripts folder; from a terminal, run it from your project folder.

If you already have work

  • A project that has a recordInstall, add the repository to your trusted list, and open a session. The brief appears on its own.
  • A codebase with months of historySay catch up the record. Claude takes a read-only inventory of the commits, issues and pull requests, proposes a topic map for your approval, and posts past events as reconstructed notes with their original dates.
  • An older trackerSay migrate the issues of octo-org/octo-repo, with your own repository. Content is copied into the new structure. Nothing in the old tracker is edited or deleted.
